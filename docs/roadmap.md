# 规划与能力差距

面向维护者、集成者和后端开发者：本页区分当前机制与待补交付，以可验证的行为作为扩展完成条件。条目不采用内部任务号，也不把框架合同写成已接通后端。

## 图模式

| 当前基础 | 待补目标 | 完成条件 |
| --- | --- | --- |
| 只有受限 CANN single-decode 声明参数更新；生产 Ascend C 不可入图 | 选择一个明确工作负载接入原生 AOT 图执行 | 固定资源、tiling/executor 与 workspace 生命周期明确；目标设备 eager/capture/replay 数值一致，地址/shape/流/漏更新负例通过 |
| 调用方拥有图，已有 ReplayParameterUpdates | 将选中 runner 与实际模型捕获/重放边界衔接 | 验证多层、重复任务、逻辑参数映射、序列化更新与失败恢复，不要求框架再持有另一张图 |
| batch wrapper 有资源/计划合同 | 建立可运行的 batch/paged 动态重放 | 提供真实后端、最大 workspace、页表/长度等可变参数边界，不能以 CUDAGraph 类名作为证据 |

新增图声明必须绑定具体 kernel、测试与环境；未完成前保持 NOT_CAPTURABLE。具体当前接口见 [图模式](npu_graph_extensions.md)，准备结果复用、异步执行桥和多 wrapper 图协调的设计见 [执行会话与图模式设计](features/wrapper-and-aclgraph-design.md)。

## Tuning

| 当前基础 | 待补目标 | 完成条件 |
| --- | --- | --- |
| 显式离线采集、保守显著性判断、本地/随包查询 | 扩大到有多个可比较实现的实际算子与 shape | 相同数学/精度/输入输出/同步和计时边界；原始样本完整，允许 winner=null，不预设某后端胜出 |
| 声明/能力/硬件/适用执行身份可校验 | 完善软件、编译与加载产物变化的统一失效 | 记录确实绑定当前运行实现，替换软件或二进制后不能复用失效结论 |
| 运行时不自动采样 | 若引入在线探索，单独定义资源和延迟预算 | 开关、触发、隔离、正确性与失败策略都接入代码并测试，不能只新增配置名 |
| 发布目录为空，已有显式导出器 | 交付经过审核的发布测量集合 | 来源可复核、大小受控、目标硬件完整，查询不绕过正常准入 |

当前 `FLASHINFER_NPU_ONLINE_TUNING` 和 `FLASHINFER_NPU_TUNING_DIR` 的显示值不代表这些目标已实现。实际存储与查询见 [Tuning](tuning.md)，显式上下文、完整候选快照与 tactic 执行交接见 [AutoTuner 设计](features/autotuner-design.md)。

## 与上游和参考项目的缺口

补齐围绕实际模型工作负载选择，不按接口名字批量创建占位注册：

- **Attention**：mixed/paged/ragged 的完整 NPU provider、统一调度及更多 MLA/sparse/POD 模式；先交付明确 envelope 和资源协议。
- **低精度**：FP4/MX/FP8 转换和存储协议、更多量化 GEMM/MoE；scale/zero-point/打包/布局与完整 dtype 组合要可验证。
- **服务框架集成**：将已有原生 kernel 与图/tuning 接入真实 forward，不把独立 runner 测试当作完整 vLLM/SGLang 模型证据。
- **通信与专家并行**：完整 moe_ep/HCCL 路径、分布式语义和多 rank 运行证据；普通 grouped GEMM 不代替它。
- **其余上游模块**：共享前缀、多级 cascade、专用状态模型和其他流水按需求选择；当前没有实现的族不作为已支持目录展示。

对齐对象和缺口按本仓现有证据划分，不据外部项目名称推断性能或完整能力：

| 对齐对象 | 本仓已有连接 | 尚未交付的部分 |
| --- | --- | --- |
| FlashInfer 固定 API 基线 | 部分直接函数、plan/run、run-only 与版本化 parity 台账 | backend 值域、签名差异、完整算子族、参数组合与生命周期的逐项等价证据 |
| vLLM-Ascend 原生算子组织 | GMM/SFA 源码移植、架构目录、本仓 AOT 与 runner | 从独立算子验收到服务框架真实 forward、图与模型级验证的完整链路 |
| 同一 op 的多后端实现 | Matmul 已有 CANN/Ascend C/Triton 共同语义 | SFA/GMM 当前只有 Ascend C，尚无同 op 的 CANN/Triton 注册与等价测试 |
| 服务框架的执行接口 | 公共函数、计划生命周期、图参数更新辅助接口 | 与 vLLM/SGLang 等具体版本、模型和调度方式匹配的集成证据 |

接口基线与当前差异见 [上游兼容性](upstream-compatibility.md)。所有扩展分别交付注册、正反例、真机数值、产物/安装、图或性能所需证据；编译、接口存在或静态扫描都不等同于完成。

## 交付顺序

先收敛已有实现的支持契约、配置和目标命名，再对选定工作负载扩展图与可比较实现，最后扩大发布与模型矩阵。保持精确登记和 ABI 护栏，不以删断言、放宽容差或忽略 skip 缩短交付过程。
