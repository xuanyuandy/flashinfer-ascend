# 特性设计

面向集成者、后端开发者和框架维护者：本目录说明跨算子的执行机制、扩展设计及验收边界。使用接口时先核对当前能力，设计中的接口不作为已实现 API。

| 主题 | 设计文档 | 当前接口与限制 |
| --- | --- | --- |
| Wrapper、原生准备复用与 NPU 图模式 | [执行会话、资源与图协调设计](wrapper-and-aclgraph-design.md) | [图模式接口与范围](../npu_graph_extensions.md)；只有受限 CANN single-decode 声明图参数更新，生产 Ascend C 均不可入图 |
| AutoTuner、tactic 搜索与选择复用 | [候选、测量、缓存与执行交接设计](autotuner-design.md) | [离线调优](../tuning.md)；已有显式采集和冠军 ID 查询，没有通用 autotune 上下文或 tactic 搜索 |

## 文档约定

- 每项特性保留一篇设计主文，说明读者、目标、当前能力、分层、接口与生命周期、限制及验收条件；使用稳定的主题文件名。
- 当前行为以源码为准，列出代码或测试入口。接口存在、编译成功、Host 合同测试和设备运行分别说明，不能互相替代。
- 新模块、协议和示例明确标为设计；未实现或未在目标环境验证的能力不写成支持声明。图能力绑定具体 kernel、SoC、输入范围与证据。
- 术语沿用 [架构](../concepts/architecture.md)，使用仓库相对路径；参考上游源码写作 `flashinfer-ori: path`。
- 保留有效代码示例与设计约束。一次性命令日志、设备自检、耗时和测试数字放在验证报告中，不混入特性正文。

当前支持以 [后端矩阵](../backends/overview.md) 为准，跨特性的扩展顺序见 [规划与差距](../roadmap.md)。
